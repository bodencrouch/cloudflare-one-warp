## Additional review quality fixes

Proxy launcher desktop Exec paths are quoted correctly and user application discovery honors XDG_DATA_HOME. Update recommendations filter architecture and direct bundle guidance points to release artifacts rather than unpublished stores. Untrusted AppImage updates remain unavailable for automatic Apply until a pinned release key and matching signature are present; manual installation remains available.

Launcher regressions cover reusing unmanaged API daemons, selecting a separate port for requested Web UI, and preserving existing credentials. Canceled firewall recovery generations cannot invoke obsolete rules or resurrect retry timers. Update-picker regressions clear old eligibility and commands, reject late responses, and only authorize a selected release after preparation returns a confirmation token. Source-upgrade guidance uses a fresh tagged checkout and targets the actual installation path.

## Validation and limits

The package checks run actual staging and alternative recipe bodies instead of matching install-command text. Native Arch makepkg and Fedora RPM builds, deb/source/formula generation, documentation builds, and dependency audits provide separate evidence from the mock daemon tests. Both Qt worker tests also passed with PyQt6 6.11.0 in an isolated Python environment. `npm run test:desktop` runs the Linux fake-host integration fixture and optional Qt worker tests; those explicitly skip when their platform or Python/PyQt6 dependency is absent.

The mock suite is not proof of real enrollment, systemd mount sandbox enforcement, KDE host settings, an installed Flatpak host bridge, native Windows executables, or macOS Homebrew installation. Store channels remain conditional on external publication and review. The direct GitHub release assets are the supported baseline described in [Distribution](DISTRIBUTION.md).
